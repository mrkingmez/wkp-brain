## Change 4: S4 PDT overshoot FIXED (software-director, order from trading-director, 2026-11-27)
- Before: hash `7a0c25c7a871b79b`, 94 tests OK. After: hash `7a0c25c7a871b79b` (config.yaml untouched, so the hash does not move; code changed, see CODE-SHA256.txt).
- Cause: `risk.pdt_block` counted only CLOSED same-day round trips. Four entries could fill on one day (all open, none closed yet), then all close the same day = 4 day trades against a limit of 3.
- Fix: `risk.pdt_block(..., open_entry_dates=())` also counts entries still open that were opened on the fill date as potential day trades against BOTH limits (rolling window and calendar month). `engine._try_fill` passes the entry dates of the book's open positions. An entry opened yesterday is not counted today.
- Reproduction: new test `test_four_same_day_entries_the_fourth_is_refused...` fills four same-day signals. On the code before the fix all four fill (checked on a scratch copy of the pre-fix code: `['AAA','BBB','CCC','DDD']`), after the fix three fill and DDD is refused with a "PDT guard" CANCEL line.
- The old demo case (4 in 5 days vs limit 3, 0 refused) did NOT reproduce on the current code: the old demo-out was stale (made before change 2). Rerunning the pre-fix code (scratch copy) gave Zac ledger 5 day trades, peak 3 in 5 days, limit 3, 0 refused, so the demo had already stopped overshooting because change 2 shifted the fills. The fix refused 0 entries in the demo (identical before and after change 4). The engine test above is the proof the guard now holds; the demo shows 0 overshoots.
- Label: because the demo now shows 0 overshoots (peak 3 vs limit 3, both ledgers), the "PDT overshoot: Zac ledger not go-live evidence until fixed (known issue S4)" text was REMOVED from the scorecard.md PDT bullet and README Known limits now says FIXED. Scorecard bullet format otherwise unchanged. Caveat kept in README: the guard can refuse entries that would never have been day-traded (conservative), rule text still not confirmed.
- Tests: `TestPdtOpenEntriesCount` (3 tests: unit boundaries incl. yesterday not counted, 2 closed + 1 open = limit refused, month limit; four same-day entries with the 4th refused and exits staying within the limit; demo-driven check that neither ledger exceeds the rolling or monthly limit). 94 before, 97 after.
