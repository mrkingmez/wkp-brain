## Design decision (why a new folder)
Existing `D:\WKP\data\firefly-prompt-guide\prompt_lint.py` (rules R1 to R13) stays UNCHANGED and keeps working (STANDARD.md and 18 agent specs call it by path). The new tool lives in `D:\WKP\software\prompt-preflight\` (software division home, tests beside code) and IMPORTS prompt_lint by path (env PREFLIGHT_LINT_DIR overrides, default D:\WKP\data\firefly-prompt-guide). One source of truth for R1 to R13, new rules are additions. Only edit prompt_lint.py to add one docstring pointer line to preflight.

## Files to build
- `preflight.py` CLI plus `check` API: `run_checks(text, meta, negative=None, history=None) -> list[Finding]`
- `rules.py` the RULE TABLE as data (id, name, severity, tag, applies, evidence, source files, fix). Single source for output text and docs.
- `gen_rule_table.py` writes `RULE-TABLE.md` from rules.py (docs cannot drift from code).
- `tests/test_preflight.py`, `tests/test_regression.py`, `tests/fixtures/` (frozen copies, see below), `tests/run_tests.bat`.
- `README.md` plain-words how-to (Zac and agents), `HOWTO` content also feeds the playbook pointer.

## Input
1. Markdown file with ```prompt blocks (existing format: ID, KIND, ENGINE, START_FRAME, AUDIO, ALLOW_IMPACT, then `---`, then the prompt). NEW optional header keys: END_FRAME (yes/no), MASTER (file name), REFERENCE_TYPE (composition/style/none), SHOT (shot id for history), MODE (new/edit), ALLOW (comma list of rule ids the author explicitly overrides, shown as OVERRIDDEN, never silent), NEGATIVE (negative-field text, may be a continuation until `---`).
2. A .txt file in the Ian format: header line `MAIN PROMPT (...)` then text, blank line, header `NEGATIVE FIELD (...)` then text. Parse main and negative separately (prompt.txt files in D:\WKP\data\firefly-prompt-log\ian-*\).
3. Any other file or pasted text (`--text "..."` or `-` for stdin): the whole text is one prompt. Flags supply the meta: `--kind still|video|edit|auto` (auto: video if it has timestamps, a camera sentence or an engine in the video list, edit if it starts with a change verb and has a Keep line, else still; print the guess), `--engine veo|kling|seedance|runway|luma|flux|firefly|other` (default other: only engine-neutral rules run), `--start-frame`, `--end-frame`, `--audio`, `--master`, `--ref-type`, `--shot`, `--history FILE`, `--record`, `--allow`, `--json`, `--quiet` (hide PASS lines), `--rules` (print table), `--no-checklist`.
Exit code 1 if any FAIL, 0 otherwise, 2 for usage error. ASCII-only console output (Windows cp1252 safe), no em dashes.

## Output (per prompt)
```
PREFLIGHT J2-strike  (veo, video, 89 words, 540 chars)   VERDICT: FAIL
[FAIL] R1   negation word 'no' ...   WHY: <plain words>   FIX: <plain words>   (source tag)
[WARN] PF01 ...
[PASS] R2 R3 ...   (one compact line of passed rule ids, hidden by --quiet)
NINE-POINT START-FRAME CHECK (video prompts, printed once per prompt): the nine points from PROMPTING-PLAYBOOK D3 plus our three extras 10, 11, 12, one line each.
LIMIT: this tool reads words. It cannot predict what an engine draws.
```
Verdict is the worst result. Each finding has: severity, rule id, reason, fix. OVERRIDDEN findings print as `[OVERRIDDEN]` and do not count as FAIL.
