# Pre-flight: Gate sign-off record

Created 2026-11-22 by studio-director. Run before a gate result goes into a package or log as "passed". One unticked item and the gate is recorded as OPEN, not passed. The signer is never the agent that made the work being gated.

| # | Check (yes or no) | Tick | Proof |
|---|---|---|---|
| 1 | The gate record names the gate, the work checked (path), the signer (agent or Zac), and the date. | | |
| 2 | The signer is not the agent that produced the work. | | |
| 3 | The verdict is one of PASS, PASS WITH NOTES, FAIL, STOP, GO, GO WITH CHANGES, quoted from the signer's own file, with its path. | | |
| 4 | Every note or send-back from the signer is listed with what happened to it (fixed, queued, rejected with a reason). | | |
| 5 | A clearance STOP is shown as its owner's call. If it was resolved, the record points to the owner's written yes or the Zac decision. The studio head does not close it alone. | | |
| 6 | Both script-room passes are logged by date and file path before the word "final" appears. | | |
| 7 | Things the gate did NOT check are written (for example "nothing heard", "platform rule not read"), not left silent. | | |
| 8 | Any unreachable desk is named and the package says so. No gate is hand-written around. | | |
| 9 | One send-back per desk is respected, and a second failure goes to Zac with both versions. | | |
| 10 | qa-director is the last gate before Zac on anything media, documents or claims related, and its report path is cited. | | |
| 11 | The gate table states the one-send-back-per-desk rule in words, and every gate row has a tag. | | |
