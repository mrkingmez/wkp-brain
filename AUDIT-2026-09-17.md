## 2. Flags

### P0 — Live naming contradiction: "Watershed"

`WKP-CHANNEL/CLAUDE.md` (the newer, actually-wired folder, locked 30 Aug 2026)
states in its first section: **"'Watershed' is a RETIRED name for What If. Do
not use it in scripts, titles, filenames, calendar entries, or agent output."**

But the name is still live in six places:
- **`CLAUDE.md`** (root) — ventures table, line 21: `Watershed / Hidden Hinge (What If) | ./WhatIF/ | 5`
- **`WhatIf/CLAUDE.md`** — an entire orphaned second venture file, last touched
  2026-08-08 (one commit, pre-dates the WKP-CHANNEL rebuild by three weeks),
  titled `# Watershed — Warrior King Productions`, and it defines Format A as
  "WATERSHED" — directly contradicting the retirement lock.
- **`Post-Production/CLAUDE.md`** line 13 — "the same gap affecting the
  Watershed video series — see whatif/CLAUDE.md"
- **`Ruby-One/CLAUDE.md`** line 27 — "the same bottleneck affecting Watershed
  applies here"
- **`WWD/CLAUDE.md`** line 81 — "Sourcing matters the same way it does for
  Watershed"
- **`TASKS.md`**'s Drive-cleanup table still routes `Watershed-SOP-v3.md` and
  `Watershed-Predictive-Model` to `WhatIF/`

Root CLAUDE.md's own routing table also points at a folder (`./WhatIF/`) that
doesn't exist — the real folder is `WhatIf/` (different case, and it's the
stale one) — while the actual live content lives at `WKP-CHANNEL/`, which
appears nowhere in the root ventures table or in `projects.md` at all.

**Net effect:** any session that reads the root table first and routes to
`./WhatIF/` lands on the retired-name version and would violate the lock
without ever seeing it was overridden. This is the single most likely
"an agent will use the wrong name in a real script" bug in the repo.
Recommend: delete or explicitly stub-redirect `WhatIf/`, fix the root table
row to point at `WKP-CHANNEL/` under its real name, and add `WKP-CHANNEL` as
its own numbered entry in `projects.md` (it currently has none).

### P0 — Two competing agents both claim Shattered Empire

`.claude/agents/fiction-director.md` (last touched 2026-08-21) and
`.claude/agents/shattered-empire-director.md` (last touched 2026-08-26, newer)
both describe themselves as the owner of Shattered Empire, with materially
different operating models:
- `fiction-director` — model `opus`, edits directly ("You are the editor"),
  tools include `Agent`, no stated log path.
- `shattered-empire-director` — model `sonnet`, routing-only ("You direct...
  you do not edit"), routes to `fiction-editing` / `fiction-alpha-feedback`,
  logs to `D:\WKP\SHATTERED-EMPIRE\logs\director.md` (note: all-caps path —
  the real folder is `Shattered-Empire`, case-different; harmless on Windows,
  would break on a case-sensitive filesystem), escalates to a
  venture-local `SHATTERED-EMPIRE\logs\DECISIONS.md` rather than the root
  `logs\DECISIONS.md` the root CLAUDE.md escalation rule specifies.

`.claude/skills/jarvis/SKILL.md`'s routing table sends "Shattered Empire" work
to **`fiction-director`** — the older of the two — so `shattered-empire-director`
looks like a newer build that never got wired into Jarvis's routing and may be
silently dead. Neither file was touched in the same session, so this reads
like a half-finished handoff rather than a deliberate two-agent design.
Recommend: pick one, delete the other, fix Jarvis's routing table to match.
